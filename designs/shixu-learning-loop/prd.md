## 1. 背景与问题

学习类产品的三个普遍失败点:

1. **坚持不下去**:断签清零式连胜让一次失败就流失;
2. **学了就忘**:投入只发生在"当时",没有对抗遗忘曲线的机制;
3. **成果看不见**:只有投入计数("学了 100 小时"),没有掌握证据;边界不可见 → 无边无界,不知道学到哪、还差哪,没法学。

拾序已有的地基:学习主题为本体、日历事件(含 category/tag 规则)、PDCA/语音转录/自我反思、本地 SQLite、本地通知、Pi Agent(工具驱动)、语音识别(原生 + 浏览器降级)。本 PRD 在此地基上补齐"学习闭环"。

## 2. 目标与非目标

**目标**

- **G1 坚持有容错**:让用户能把一个学习目标坚持完整周期(默认 100 天),失败不清零、可冻结、可恢复。
- **G2 成果不流失**:学过的内容按遗忘曲线被安排复习,以"取出"而非"存入"为准。
- **G3 边界可见**:让"学会了什么、还差什么"可见——学习被装进有限容器,动力有终点。
- **G4 AI 只做生成不做审判**:Pi 承担拆解、出题、教回评估、复盘等生成类工作;成败判定交给规则,变更可由用户确认与撤销。

**非目标(明确不做)**

- 不做服务端、账号、排行榜、社交 feed;分享仅为本地导出图片。
- 不做惩罚机制(掉血、清零、破产)。
- 不做云端同步、牌组/卡片市场。
- 钉钉导入的 `work` 事件不参与学习闭环的全部功能。

## 3. 核心命题与设计原则

**核心命题:有边界才有学习的动力。** 无边无界没法学习——挑战是**时间容器**(100 天一定结束),复习队列是**数量容器**(今天 N 张,做得完),掌握地图是**空间容器**(主题边界可见,"学会"长什么样)。终身学习在元层面无限,但每个交互单元有限、可收尾([目标梯度效应](https://www.ux-strategy.ch/en/effects/goal-gradient.html):越接近终点动力越强,前提是终点看得见)。

设计原则:

1. **学习主题为本体**:挑战、卡片、知识点都挂在主题下;日历事件本体不被任何闭环功能修改。
2. **离线优先,公开可选**:打卡、复习、地图全本地;分享是显式导出,无账号无网络依赖。
3. **AI 只做生成和提醒,不做审判**:调度与判定交给规则;AI 输出一律建议制。
4. **宽容的失败观**:冻结卡、不清零;复习忘掉不惩罚,只重排。
5. **成果可见边界**:亮区与暗区同等呈现;用推进叙事替代总分叙事。
6. **一切皆有限容器**:每个交互单元可完成、可收尾;拒绝无限信息流式设计。
7. **启动零摩擦**(2026-11-03 增补,design-draft §六):从"想学"到"动手"只隔一个动作;每主题常驻唯一"现在就做",任务带 2 分钟微版。
8. **反馈即引导**:反馈必答三问(到哪了/怎么样/下一步),终点是可点击的动作,不是句号;不做人格表扬与焦虑设计。

## 4. 用户故事

- **US1(开始)**:我想学"统计学基础",对着 AI 说一声,Pi 帮我把目标拆成知识点清单和一份 100 天挑战,我确认后开跑。
- **US2(没空的某天)**:今天实在没学,第二天打开 App,挑战自动用掉一张冻结卡保住连续,我无压力继续。
- **US3(日常复习)**:晚上收到一条通知"今日 12 张复习",打开做完 15 分钟,队列清空,关掉 App,今天完成。
- **US4(检验真懂)**:对手机讲 2 分钟"什么是 p 值",Pi 对照知识点清单告诉我讲清了哪几点、漏了哪几点。
- **US5(看边界)**:打开主题详情页,掌握地图上亮区在扩大、边缘在呼吸、暗区只剩轮廓;周报告诉我"边界本周推进到哪里"。

## 6. 模块需求要点

- **F1 百日挑战**:绑定单一学习主题;门槛二选一(≥1 个完成事件 / ≥N 分钟);冻结卡 2 张、补签 24h 内 1 次、连漏 2 天暂停(Pi 询问继续或重排);里程碑 3/7/21/50/100 天,早期权重高。验收方向:从创建到 100 天的全状态流转可在离线环境闭环。
- **F2 复习队列**:卡片必须锚定来源(事件笔记/转录,可溯源);三档自评(忘/模糊/记得)驱动 SM-2 间隔;队列上限 20 张/天、新卡日入队 ≤10。验收方向:完成一轮复习后,卡片 due 正确后移,忘掉不清零只重排。
- **F3 掌握地图**:Pi 按逆向设计拆知识点(Bloom 分级),用户可增删改;四态 dark/touched/shaky/mastered 由规则驱动;掌握百分比只数 shaky+mastered(防止"接触过"计入掌握)。验收方向:仅凭复习与教回数据,四态可自动流转且用户可见其变化。
- **F4 本地通知**:每日 ≤2 条,22:30 后不推送,时段用户可配;文案由 Pi 个性化,离线退化为模板。
- **F5 费曼教回**:2 分钟语音 → 转录 → Pi 输出"覆盖/遗漏"清单;覆盖项触发掌握度更新,遗漏项**不自动降级**,生成建议由用户确认。
- **F7 分享卡片**:第 N 天 + 一句话 PDCA + 热力图切片,本地渲染成图,显式分享。

## 7. AI(Pi)需求

| 工具 | 一句话职责 |
| --- | --- |
| `create_challenge` | 对话式创建挑战并起草目标笔记 |
| `draft_cards` | 从 PDCA/转录起草复习卡草稿,用户确认入库 |
| `challenge_reminder` | 挑战与复习通知文案个性化 |
| `challenge_review` | 阶段复盘草稿(事件 + PDCA + 复习日志) |
| `challenge_pause/resume` | 红线后的继续/重排对话 |
| `assess_teachback` | 教回转录对照知识点清单评分 |
| `frontier_report` | 周/阶段边界报告:亮区扩大、边缘摇晃、暗区轮廓 |

信任边界:Pi 全部输出为**建议制**(草稿、确认、可撤销);模型凭据仅经 HTTPS 发往所配置推理端(DeepSeek/GLM),不落 SQLite、不进日志、不持久化于服务端(遵循 AGENTS.md 安全约束)。

## 8. 成功指标与护栏

- **北极星:周复习完成率**(当周队列内被处理的卡片占比)。目标 ≥60%(假设值,上线后校准)。
- 假设性指标:挑战 21 天存活率 ≥40%;教回周使用 ≥1 次/活跃用户;主题掌握地图"边缘区"周缩小率 > 0。
- 护栏指标:通知关闭率 <20%;连续 7 天打开但 0 复习的用户占比(流失前兆)。
- **古德哈特防线**:掌握度、打卡数据只对用户本人可见,不参与任何排行或分享刺激;产品指标不进入用户界面叙事。

## 9. 依赖与约束

- 存储:@capacitor-community/sqlite(Android 真身),浏览器 localStorage 降级(仅开发预览)。
- 通知:@capacitor/local-notifications,本地调度。
- 语音:@capacitor-community/speech-recognition(原生),浏览器 SpeechRecognition 为预览降级。
- AI:Pi Agent 运行时,DeepSeek / Zhipu GLM,仅 HTTPS;凭据存 Android Keystore 安全存储(capacitor-secure-storage-plugin)。
- UI:入口位置与呈现强度须与 C 系统 12 屏设计稿对齐(待设计稿确认)。

## 10. 风险与对策

| 风险 | 对策 |
| --- | --- |
| AI 出的卡片质量差、用户不信任 | 逐张确认入库;卡片必须可溯源到原文;可删改 |
| 队列堆积导致弃疗 | 20 张上限 + 缺席自动冻结 + 暂停机制 |
| 知识点拆解过粗(边界失真)或过细(负担) | Pi 拆初稿、用户删减;知识点支持随时增删 |
| 通知疲劳 | 每日 ≤2 条、时段可配、门槛未满足才发 |
| 掌握度自欺(自评虚高) | 只数 shaky 以上状态;教回通道提供外部校准 |

## 11. 开放问题

1. 一个主题是否只允许一个活跃挑战(建议:是)。
2. 轻打卡是否强制附一句 PDCA。
3. 复习算法起点 SM-2 还是直接 FSRS(建议:先 SM-2,表结构已预留)。
4. 掌握地图在主题详情页的入口层级与暗区视觉强度(待设计稿)。
5. 挑战与既有"习惯"功能的关系(特例还是并列)。
6. 知识点拆解粒度基线(建议 Pi 拆初稿 + 用户删减)。
